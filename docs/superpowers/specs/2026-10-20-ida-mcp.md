# IDA MCP integration design

The user requested complete implementation after approving the proposal to add IDA MCP to WireFit, using the installed IDA Professional 9.3 at E:/IDA Professional 9.3. Deliver an installed compatible MCP runtime, a distinct IDA evidence adapter, real asynchronous jobs, CLI/MCP entrypoints, and a usable workbench view. Continue implementation without another approval round.

## Architecture and scope

Use a pinned community mrexodia/ida-pro-mcp source revision compatible with IDA 9.3. The current official Hex-Rays MCP requires IDA 9.4+, so do not silently upgrade IDA. Install dependencies in a WireFit-owned isolated environment. Preserve the installed IDA and all licensing files. Do not run activation bypasses or key generators.

WireFit is an MCP client to the IDA server, separate from its pinned REA client. Add src/ida/ modules for request validation, transport/lifecycle, normalized evidence and job persistence. Reuse CaseStore, JobManager, artifacts and reporting. IDA pseudocode and microcode are not Ghidra p-code and never enter the existing lifter under another provider name.

The initial product surface performs read-only static analysis of a copied input: metadata, paginated functions/strings, function disassembly/decompilation/CFG/callers/callees, cross references, raw bytes, and types, using explicit allowlisted MCP tools. No arbitrary Python, assembly patches, debugger launch or client-supplied backend argv is exposed in the browser. Keep GUI connection ownership separate from IDB ownership; never close a user-owned GUI/database during WireFit cancellation. Prefer a dedicated owned headless database per job; its work is copied into a case-specific staging directory. Direct MCP launch/configuration is also documented for external clients.

## Contracts

IdaAnalysisRequest: {file:string,queries:IdaQuery[],timeout_ms?:number}. Max 16 queries, timeout 1..600000 ms, filename <=4096 chars, regular input <=128 MiB, no links. IdaQuery is one of overview; functions or strings with optional pattern/offset/limit; function or xrefs with address; bytes with address/size; types with optional pattern/offset/limit. Address is canonical 0x hex <=64 bits; offsets <=1000000, limits 1..200, byte size 1..4096, pattern <=256. Additional fields and arbitrary tool names are rejected. Queries are read-only. Exact upstream argument schemas are fixed after inspecting the pinned runtime.

IdaAnalysisResult: {result_id,operation:'analyze_ida',status:'completed'|'partial'|'failed'|'cancelled',source:{path,sha256,size_bytes,artifact},provider:{id:'ida',version,server,revision},database:{...identity},queries:[{query,status,data?,error?,artifact?}],artifacts:ArtifactRef[],error?,limitations,validation:{source_unchanged,runnable_verified:false,whole_program_equivalence:false},cleanup:{...}}. Persist each raw MCP reply and tool catalog; retain failures and truncation. A partial report remains available even when some queries fail. No native execution or mathematical proof is implied. Stable normalized fields may support graph and code display; raw replies remain inspectable.

Expose `submitIdaAnalysis(service,request,configuration?)` and capability probe/config loader from src/ida/index.ts. Runtime config at .local/ida-mcp.json selects only administrator-installed executable/args/env, pins source identity, and is never supplied through HTTP. Web POST tasks adds {kind:'ida',file,queries,timeout_ms?}; bootstrap ida capability is optional when not installed. Workbench GET case results and artifact API carry the report. CLI `wirefit ida status` and `wirefit ida analyze --case CASE --file FILE --query QUERIES.json` use the same adapter; wirefit MCP gets an asynchronous analysis tool.

## Workbench

Add an IDA analysis view in existing navigation. Show actual installed/probed state and version, explicit file path, query builder, writable destination case, submit/progress/cancel/export, completed and partial query results, pseudocode/listing text, xrefs/CFG where available, and raw hashed evidence. Reuse same-origin token and existing job ownership. Never show a connection as a successful decompilation. Historical managed cases remain read-only; new jobs use the writable workbench or a UI-created case. Readonly results can be viewed.

## Acceptance

Run real MCP handshake/tools/list, IDA library/IDAPython initialization, source-owned fixture disassembly, decompilation, xrefs/bytes and persisted evidence. Perform bounded static vmde research queries against an explicitly identified source/dump; do not run vmde. Verify cancellation/timeout does not leave an owned worker and does not affect user IDA. Run regression and real Edge UI tests, restart deployed workbench with the new backend, document exact versions/hashes, supported and unavailable capabilities. A real runtime blocker must be retained honestly while independent adapter/UI work continues; no mock is substituted for actual IDA success.

## Constraints

All text IO explicitly UTF-8. No Git repository exists; work in place with exclusive file ownership. Do not modify frozen native tracing tools or research evidence. No changes to original vmde. Desktop helpers use hidden windows. Network-facing services bind only 127.0.0.1. Existing WireFit tests and browser flows remain valid.
