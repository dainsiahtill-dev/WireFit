# IDA MCP Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development with parallel ownership, TDD and independent final review. The user requested full execution; proceed continuously.

**Goal:** Install and integrate real IDA 9.3 MCP into WireFit and its visual workbench.

**Architecture:** A pinned local MCP runtime feeds a distinct read-only IDA adapter. CaseStore/JobManager retain requests, raw replies, normalized reports and failures; CLI, WireFit MCP and browser share the adapter.

**Tech Stack:** Python 3.14/IDA 9.3, pinned ida-pro-mcp, Node24 TypeScript MCP SDK, existing HTML/SVG workbench, Vitest and Edge Playwright.

**Spec:** ../specs/2026-10-20-ida-mcp.md

## Global Constraints

- All text reads and writes explicitly UTF-8.
- No license changes, target execution, frozen-tool/evidence changes, arbitrary browser Python or backend argv.
- Strict finite query union and bounded input/reply sizes; copied inputs; honest partial failures.
- IDA provider stays separate from REA/Ghidra lifting; cancellation affects only owned work.
- No Git repository; parallel exclusive file ownership and no fabricated commits.

## Review Focus

- Stale GUI/database ownership cannot become permission to close user sessions.
- A reply with tool-level error cannot become successful analysis.
- Pseudocode does not prove behavior or grant original-target fidelity.
- Absolute addresses and input/database identities cannot be silently mixed.
- Cancellation/timeouts must retain partial evidence and clean owned workers.
